# 用量模块

## 数据流

各 Agent 的适配器在增量读取时一并提取 Token、请求身份、时间、推理强度和结果。失败请求保留可用的 HTTP 状态、错误类型和消息。`normalize` 负责去重、计算累计差额及识别继承的历史。`events/index` 更新请求索引，`summary` 和 `events` 分别读取汇总和分页。失败请求缺少 Token 时仍保留。累计差额只计入 Token 用量。

应用运行时自动采集。文件通知触发增量读取，每分钟补查目录。数据目录尚未创建时监听最近的已有父目录。读取失败会退避重试，也可在用量页点「立即检查」。同步状态显示最近一次有新数据入账的时间。

首次完整扫描及索引成功后，`usage_sync_state` 记录该 Agent 的覆盖范围。空目录也可完成检查。局部同步、失败或取消均不能建立该基线。页面在首次同步期间先显示已入账小计，后续查询基于同一 WAL 快照，写入大事务时仍可读取上次提交的结果。

## 存储

账本位于 `~/Library/Application Support/Agent Session Manager/usage-ledger-v1.sqlite3`。账本、WAL 和 SHM 文件权限为 0600，使用 WAL 和 FULL 同步提交。备份运行中的账本须使用 SQLite backup API。

账本按来源和会话保存计量观测及身份关系，会话正文留在源日志。账本没有保留期限。源日志被删除、截断、替换或移走后，已入账计量仍可查询。路径被复用时，各会话保留各自的累计序列。已删除的父日志保留身份关系供 Codex 和 Pi 去重。发生损坏或写入失败时保留原账本并报告错误。

可重建的缓存保存文件状态、解析版本和 JSONL 读取偏移。未变化文件可跳过读取。已入账载荷按最近更新时间淘汰，预算为 64 MiB，文件状态、SQLite 页和待导入的旧数据另计。变化来源的载荷若已淘汰，会重读该来源并与账本归并。

首次同步先导入 0.1.23 缓存中的历史计量，包括已删除源日志留下的记录。旧缓存须成功入账或重新采集后才可清理，无法解码的载荷保留原字节。

账本结构版本 5 使用 Zstandard 压缩原始 JSON，读取兼容旧 TEXT 与新 BLOB。表间通过整数来源 ID 引用路径，完整身份键保留。迁移使用单个事务，成功后通过 `VACUUM` 回收空间，失败则下次重试。降级请使用升级前的备份。

### 索引与查询

`usage_source_keys` 索引会话和请求身份、继承关系及 OpenCode 副本。索引按变化的来源及其关联会话归并，稳定请求 ID 用于更新已有行。迁移时才执行全量重建。旧来源保留的身份关系可用于关联迟到的计量，修正累计差额。

请求和用量统计均读取 `usage_request_events`。时间筛选按日志中的发生时间，使用本地日历的左闭右开区间。今日按实际小时分桶，保留夏令时回拨的重复小时，较长区间按本地日期处理。缺少发生时间的记录只出现在「全部」范围。分页按时间和 ID 倒序，页数据、总数及修订号共用一个快照。后台更新以当前可见请求为锚点，锚点已被归并时按原页码定位。

## 会话删除

`preserve_before_delete` 在删除前保存最后一批可读取的计量。保存失败时保留会话，以便重试。用外部工具立即删除或从未落盘的记录可能无法补采。

Qoder 和 Claude Code 按删除清单读取主日志和相关子会话。局部同步沿用完整数据目录的缓存范围，避免清理其他会话并保留跨来源去重。同步前后检查文件集合、版本与身份，执行删除前再次核对清单。其他支持删除的 Agent 按来源同步。

## 数据源约定

- **Claude Code** 以稳定的响应 ID 归并流式分块，读取 progress 中的子 Agent 调用。Advisor 和降级前后的独立调用分别计量。缓存写入使用总量或完整的 TTL 分项。存在 `api-request.id` 与 `assistant.requestRef` 时，可用开始日志和响应结束时间计算耗时。
- **Qoder** 的缓存包含关系未确认时用已记录的输入和输出作为总量下限。Claude 和 Qoder 的 UUID 消息 ID 视为全局身份，短 ID 限于对应会话。
- **Codex** 优先使用单次响应计量。逐响应记录和累计通知先去重，再补未覆盖的累计差额。分页 `history_base` 使用精确边界。父线程身份与实际分叉分别记录。回放按父线程已知计量和分叉边界识别。耗时根据用户消息、上一响应或工具结束后的用量通知估算。TTFT 无法定位到单次请求时保留整轮口径。压缩请求和累计差额的耗时留空。源日志无法重读时，已采集的 Token 仍可查询，旧版错误估算会隐藏。
- **OpenCode** 从消息读取 Token、推理强度、服务档位和请求元数据，项目目录优先取自会话。耗时优先使用有效的 `time.streamed`，其次使用 `time.completed`。存在 `time.firstToken` 时读取 TTFT。V2 按分叉序列边界识别副本，旧记录使用原始请求时间、模型、Agent 和路径。副本只补原始调用缺失的历史。同一时间和计量的独立原始请求分别保留。
- **Pi** 从会话读取项目、模型快照、推理强度与时间。短条目 ID 只在同一父分支链内去重。
- **Antigravity** 从 `steps` 和 `gen_metadata` 读取用量和计时，按消息、响应或提供商 ID 合并副本。缺少身份时使用已确认的步骤匹配。

缺失字段与实际零值分别记录。后续完整响应可补齐同一请求的缺项。汇总保留缺项标记，旧账本中缺少标记的零值按未知处理。采集字段变化时更新对应解析版本，使现存日志可补齐旧记录。请求结果与 agent-events 一致。检测到错误时记为失败，其余记录归为成功。TPS 等于输出 Token 除以请求总耗时（秒）。失败请求与累计差额留空。

## 模型价格

- 请求费用按模型价格和 Token 用量估算。有费用无法计算时，汇总以 `≥` 标记已计入的金额。
- 报价依次采用自定义价格、内置价格、Models.dev 参考价和 LiteLLM 参考价。模型 ID 以 `-free` 或 `:free` 结尾时，内置价格为零。
- 优先匹配完整模型 ID；渠道未知时可回退到原厂报价。精确报价缺失时支持忽略 `-low`、`-medium`、`-high` 或 `-xhigh`。其他匹配均未命中时，`deepseek-v4.1-flash` 和 `deepseek-v4.1-flash-1017` 使用 `deepseek-flash` 的报价。同名报价冲突时保留未定价状态。
- Models.dev 和 LiteLLM 的公开价格目录独立缓存。更新失败时继续使用上次取得的价格。单价统一为美元 / 百万 Token。
- 自定义价格保存在应用数据目录的 `pricing/custom-prices.json`，权限为 0600，采用原子写入。支持 USD 和 CNY，按 `1 USD = 7 CNY` 统一汇总为 USD。估算在查询时使用最新价格。账本保留原始记录。
- 缓存读写从总输入扣除后单独计算，推理已包含在输出。Qoder 有非零缓存且无法确认归属时跳过估算。缺少缓存读写价格时使用输入价。Claude Code 记录的 1 小时缓存写入在缺少单独费率时按输入价的两倍估算。
- 输入超过长上下文阈值时，整次请求使用长上下文价格。同渠道、同模型的 LiteLLM 报价可补齐 Models.dev 缺少的服务档位。Codex `priority` 缺少单独报价时使用标准费率的两倍。

升级、新建和追加三组对照的完整来源观测、请求事件及完整身份关系 SHA-256 相同，完整统计及请求数一致。追加只读取 7,840 新字节，请求从 63,500 增至 63,510；未变同步读取 0 字节。本机账本的只读备份（2,432 个请求）也通过同样逐项比对，账本加缓存从 35.48 降至 7.88 MiB（减少 77.8%），升级约 83 ms；其热同步 0.134→0.154 ms、首/末页约 0.14–0.15 ms，属于小样本下的轻微波动。
